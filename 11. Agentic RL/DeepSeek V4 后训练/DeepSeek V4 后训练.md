# DeepSeek-V4 后训练：领域专家、GRM 与 OPD

> 本笔记整理 DeepSeek-V4 技术报告的后训练设计：领域专家培养、生成式奖励模型（GRM）、在策略蒸馏（OPD）、工具交互及后训练基础设施。

## TL;DR

DeepSeek-V4 的后训练并非单一通用模型按传统 `SFT → RM → PPO` 串行推进，而是：

```text
高质量领域数据
    ↓
领域专家：SFT → GRPO/RL → 数学、代码、Agent、指令跟随
    ↓
多教师在策略蒸馏（OPD，反向 KL + 全词表 logits）
    ↓
统一模型
    ↓
FP4 QAT、可恢复 rollout、百万上下文 RL、Agent 沙箱
```

关键思想：先让不同领域独立达到较高能力，再在学生策略自身 rollout 的分布上整合；开放任务以 GRM 和 rubric 取代单标量奖励的不足。

## Fast Look

### 领域专家培养（Domain Expert Cultivation）

- **描述**：针对数学、代码、Agent、指令跟随等目标域分别训练专家；先做高质量领域 SFT，再以 GRPO 和针对性奖励继续强化。
- **与传统通用后训练的区别**：传统流程通常让一个通用模型在混合任务上统一 SFT/RL；该路线先解耦优化、后整合能力。
- **优点**：减少多目标相互干扰；各领域可使用专用数据、验证器和奖励；能力瓶颈更容易定位。
- **缺点/注意点**：须维护多教师、数据管线和评测集；专家间可能出现策略冲突，整合不保证每项能力无损保留。

### SFT（Supervised Fine-Tuning）

- **描述**：在领域高质量示范上最小化目标回答 token 的交叉熵，为专家建立可用初始策略。
- **与预训练的区别**：预训练学习广泛 next-token 分布；SFT 显式学习任务格式、工具协议和高质量解题轨迹。
- **优点**：稳定、可扩展，为后续 RL 提供合理行为先验。
- **缺点/注意点**：只能模仿示范上限；开放任务的唯一参考答案往往不足以表示偏好或过程质量。

### GRPO（Group Relative Policy Optimization）

- **描述**：对同一 prompt 采样一组回答，按组内相对奖励估计优势并更新策略；报告将其用于领域专家的强化阶段。
- **与 PPO 的区别**：PPO 常依赖 critic/value model 估计优势；GRPO 可用组内相对结果，降低对独立 critic 的依赖。
- **优点**：适合可验证的数学、代码等任务；能利用同题多 rollout 的相对信息。
- **缺点/注意点**：仍依赖高质量奖励/验证器；组大小、奖励方差和采样成本会影响稳定性。

### 推理努力模式（Non-think / Think High / Think Max）

- **描述**：报告区分非思考、较高推理努力和最大推理努力三种模式；后两者使用更长的显式推理，面向复杂求解与规划。小红书后训练拆解进一步称 Max 会在 system prompt 前加入额外提示以鼓励更深思考；该实现细节待以官方 PDF 逐页核验。
- **与单一推理预算的区别**：将测试时计算作为可调资源，而非所有请求使用相同长度的推理。
- **优点**：可将时延和成本与任务难度匹配；高难 Agent/推理任务能获得更多计算预算。
- **缺点/注意点**：更长思考不必然正确，且增加响应时间、token 成本和过度思考风险；应以任务级评测确认收益。

### GRM（Generative Reward Model，生成式奖励模型）

- **描述**：对难以自动验证的任务，使用 rubric 驱动数据训练可生成评价/依据的模型来评估策略轨迹；报告称对 GRM 也应用 RL 优化，使模型兼具生成与评价能力。
- **与标量 Reward Model 的区别**：标量 RM 只输出一个分数；GRM 可输出结构化评价、理由或更丰富的质量信号。
- **优点**：更适合开放式写作、研究与 Agent 轨迹；rubric 可显式表达多维质量标准。
- **缺点/注意点**：GRM 同样会幻觉和偏置；评价文本不等于可靠，仍需校准、对抗样本和人工抽检。

### 工具调用协议：`|DSML|` 与 XML 格式

- **描述**：报告提出用专用 `|DSML|` token 和 XML 风格结构表达工具调用，以减少转义和解析错误。
- **与自由文本/松散 JSON 的区别**：将调用边界、参数和工具结果明确编码为训练与推理协议的一部分。
- **优点**：提高工具调用可解析性，便于 Agent 训练时保留完整交互轨迹。
- **缺点/注意点**：价值依赖客户端与训练模板一致；schema 校验、权限控制和工具结果可信度仍需系统层保证。

### 交错思考（Interleaved Thinking）与 Quick Instruction

- **交错思考描述**：工具调用场景保留跨轮完整推理历史；一般对话在下一轮用户消息到来时丢弃前一轮推理。
- **Quick Instruction 描述**：在输入末尾追加专用 token 表示是否搜索、意图识别等辅助任务，并复用 KV Cache 避免重复 Prefill。直读笔记以 `<|action|>` 后接搜索动作为示意；它是控制任务 token 的例子，不应与工具调用的 `|DSML|` 协议混为同一套语法。
- **与固定保留/重跑完整提示的区别**：按工具状态选择推理持久化，并以尾部增量完成轻量控制任务。
- **优点**：工具任务可维持计划与观察链，同时降低辅助判断延迟。
- **缺点/注意点**：伪装工具结果为用户消息的框架可能无法触发工具上下文；推理持久化会带来隐私、上下文和错误累积风险。

### OPD（On-Policy Distillation，在策略蒸馏）

- **描述**：多个领域专家作为教师；学生从自身策略采样轨迹，并以加权反向 KL 逼近专家分布：`L_OPD = Σ wᵢ · D_KL(π_student || π_expert_i)`。
- **与离线 SFT/前向 KL 蒸馏的区别**：学生在自身 rollout 分布上学习，减少 teacher-forcing 与真实策略分布的偏移；报告强调反向 KL。
- **优点**：在统一模型中整合多领域专家，训练信号与部署时学生策略更一致。
- **缺点/注意点**：需要学生采样、多教师和权重调度；反向 KL 可能偏向高概率模式，权重 `wᵢ` 直接决定能力取舍。

### 全词表 Logit 蒸馏（Full-vocabulary Logit Distillation）

- **描述**：保留教师完整词表 logit 分布计算 OPD 损失，而非只蒸馏采样 token 或 top-k 候选。
- **与硬标签/截断 logit 蒸馏的区别**：监督更完整地保留教师对替代 token 的相对偏好。
- **优点**：梯度估计更平滑，理论上更忠实迁移专家策略细节。
- **缺点/注意点**：词表级通信、存储和计算昂贵；教师调度、融合 kernel 与数值精度是实现关键。

### FP4 QAT（Quantization-Aware Training）

- **描述**：在后训练阶段让模型适应 FP4（报告指 MXFP4），覆盖 MoE 专家权重与 CSA 索引器 QK 路径；索引分数进一步由 FP32 降为 BF16。
- **与部署后量化的区别**：PTQ 在训练完成后量化；QAT 在训练中模拟或使用低精度，使模型主动适应量化误差。
- **优点**：降低推理内存流量与计算，缩小训练精度与部署量化模型间的行为差异。
- **缺点/注意点**：训练更复杂且依赖硬件数值格式；应同时验证任务质量、KV 召回和端到端延迟。

### 可抢占容错 Rollout：Token WAL 与 KV Cache 恢复

- **描述**：每生成一个 token 即写入预写日志（WAL）；任务被抢占时保存未完成请求的 KV Cache，恢复时依据 WAL 和缓存继续 Decode。
- **与丢弃重跑的区别**：将 rollout 视为可恢复长任务，而非中断后从 prompt 重新生成。
- **优点**：降低大规模 RL rollout 的资源浪费，提高集群抢占与故障场景下的利用率。
- **缺点/注意点**：需要一致性、存储吞吐和日志清理策略；KV 持久化带来额外 IO、隐私和版本兼容问题。

### 百万上下文 RL 与 Agent 沙箱（DSec）

- **百万上下文 RL 描述**：将 rollout 数据拆为轻量元数据与重型逐 token 字段；前者内存中全局 shuffle，后者用共享内存加载，减少节点内复制。
- **DSec 描述**：报告中的 Agent 执行平台，提供 Function Call、Container、microVM、fullVM 四层隔离基底。
- **与普通单机训练/执行的区别**：把超长轨迹数据管线与 Agent 环境隔离作为一等基础设施问题。
- **优点**：支持长上下文 RL 的数据吞吐，并能按风险/兼容性选择隔离等级。
- **缺点/注意点**：系统复杂度高；沙箱不等于绝对安全，仍需网络、文件、凭据、资源配额和审计策略。

## 与传统 RLHF 的对比

| 维度 | 传统 SFT → RM → PPO | DeepSeek-V4 报告中的路线 |
| --- | --- | --- |
| 能力培养 | 通用策略逐步对齐 | 多领域专家各自 SFT + GRPO/RL |
| 开放任务评价 | 常用标量 RM | rubric 驱动的 GRM |
| 能力整合 | 单模型继续 RL 或混合数据 SFT | 多教师 OPD 合并为统一学生 |
| 蒸馏信号 | 参考答案或有限 token 信号 | 学生 on-policy rollout + 全词表 logits |
| 部署一致性 | 训练后再做量化/服务优化 | 后训练阶段纳入 FP4 QAT、容错 rollout 与长上下文 RL 基础设施 |

## 面试回答框架

**Q：DeepSeek-V4 后训练最大的变化是什么？**

1. 先训练领域专家，而非直接让单一通用模型承受所有目标。
2. 专家阶段采用高质量 SFT 加 GRPO/RL；开放任务用 GRM 与 rubric 补足标量奖励。
3. 最后用多教师 OPD，在学生自身 rollout 分布上做全词表反向 KL，合并专家能力。
4. 收益是专精与整合分离、部署行为更一致；代价是教师调度、全词表蒸馏、长轨迹 rollout 和系统基础设施都很重。
