# 09.大语言模型评估

## Fast Look

**评估链路**：`任务定义 → 数据集/切分 → 指标 → 自动/人工/LLM 裁判 → 错误归因 → 回归集`；幻觉需按“事实、忠实性、上下文和任务风险”分层，而不是只统计一个正确率。

#### Benchmark、Leaderboard 与数据污染

- **描述**：Benchmark 用固定题集和指标比较能力，Leaderboard 汇总模型结果；数据污染指评测题或近似答案进入训练语料。
- **与线上评测的区别**：Benchmark 更可复现，线上样本更贴近真实分布。
- **优点**：便于横向比较和版本回归。
- **缺点/注意点**：刷榜、训练泄漏和任务分布偏移会高估真实能力；应保留私有 holdout 与时间切分。

#### 自动指标：Accuracy、EM、F1、ROUGE/BLEU 与 Pass@k

- **Accuracy/EM/F1**：适合分类、抽取和短答案；**ROUGE/BLEU**：按 n-gram 与参考文本重叠评分；**Pass@k**：多次采样中至少一次通过测试的代码/推理指标。
- **与人工判断的区别**：自动指标低成本、可批量回归，但通常只代理真实质量。
- **优点**：稳定、快速、适合 CI 和模型迭代。
- **缺点/注意点**：开放回答可能语义正确却低分，字面相似也可能事实错误；指标必须匹配任务。

#### 人工评测与 LLM-as-a-Judge

- **人工评测描述**：由标注者按 rubric 判断正确性、帮助性、安全性等；**LLM Judge**：让强模型按 rubric 评分或 pairwise 比较。
- **与固定自动指标的区别**：能评估开放性、风格和复杂质量维度。
- **优点**：人工可信度高；LLM Judge 可显著扩展规模。
- **缺点/注意点**：人工成本高且有一致性问题；Judge 存在位置、长度、自我偏好和提示敏感偏差，需校准与抽检。

#### 幻觉：事实性、忠实性与上下文冲突

- **事实性幻觉**：生成与世界事实不符；**忠实性幻觉**：与提供文档/工具结果不符；**上下文冲突**：遗漏或错误整合多段证据。
- **与普通错误的区别**：幻觉常以自信、流畅形式输出不可支持内容，风险更隐蔽。
- **优点**：细分类型能将问题定位到知识、检索、提示或解码环节。
- **缺点/注意点**：类别可重叠；“模型不知道”与“检索没找到”需要分别记录。

#### 幻觉缓解：数据、提示、RAG、解码与验证

- **数据/训练**：提高事实数据与偏好质量；**提示**：要求引用、不确定时拒答；**RAG**：提供可更新证据；**解码**：降低过度随机性；**验证**：用规则、检索或工具复核关键结论。
- **与单点修复的区别**：幻觉是系统问题，必须按根因组合治理。
- **优点**：可建立可观测、可回归的质量防线。
- **缺点/注意点**：任何一项都不能保证零幻觉；高风险领域必须保留人工复核和失败兜底。
