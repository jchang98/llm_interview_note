# LeetCode 高频面试题

## Fast Look

**刷题链路**：`题目数据结构 → 不变量/状态定义 → 模板选择 → 边界处理 → 时间空间复杂度`。先从完整的 [LeetCode Hot100](./LeetCode%20Hot100/LeetCode%20Hot100.md) 按模块复习，再单独手写下列高频题。

#### 最长递增子序列（LIS）

- **描述**：求最长严格递增子序列，常用 `dp[i]` 的 `O(n²)` 解法或维护最小结尾数组的二分 `O(n log n)` 解法。
- **与之前方法的区别**：相对连续子数组问题，子序列可跳过元素；贪心数组只保证每个长度的最小结尾，不直接保存完整答案。
- **优点**：覆盖 DP 状态定义、二分优化和路径恢复，是序列 DP 的核心模板。
- **缺点/注意点**：`lower_bound` / `bisect_left` 对应严格递增；非递减需调整二分边界。

#### 岛屿数量与最大岛屿面积（200 / 695）

- **描述**：把二维网格看作图，用 DFS/BFS 泛洪遍历连通块；200 统计块数，695 统计单块面积最大值。
- **与之前方法的区别**：相对一维数组遍历，状态扩展到四方向邻居；相对并查集，DFS/BFS 更直接地获取面积。
- **优点**：一个模板覆盖连通分量、边界填充、最短路径等大量网格题。
- **缺点/注意点**：必须在访问时标记；递归 DFS 要注意 Python 递归深度，BFS 要控制队列内存。

#### LRU Cache

- **描述**：哈希表定位节点，双向链表维护最近使用顺序；`get`、`put` 均为 `O(1)`。
- **与之前方法的区别**：相对只用哈希表，额外需要维护访问顺序；相对普通队列，双向链表支持已存在节点 `O(1)` 删除/移动。
- **优点**：是缓存淘汰策略与“哈希表 + 链表”组合的标准面试题。
- **缺点/注意点**：容量为 0、更新已有 key、淘汰尾节点和 dummy head/tail 的断链是高频 bug。

#### MHA / MQA / GQA 手写

- **描述**：多头注意力及其 KV 共享变体；分别关注 Q/K/V 投影、reshape、scaled dot-product attention 与输出拼接。
- **与之前方法的区别**：MHA 每个 Q 头独立 KV；MQA 共享一组 KV；GQA 让多组 Q 共享一组 KV，在质量和 KV cache 成本之间折中。
- **优点**：连接算法题的张量操作与 LLM 架构面试，适合手写 shape 推导。
- **缺点/注意点**：实现时要核对 `batch/head/seq/dim` 维度、causal mask、KV repeat 和数值稳定 softmax。
