# 08.检索增强rag

## Fast Look

**系统链路**：`文档解析 → Chunking → Embedding/索引 → Query Rewrite → 召回 → Rerank → 上下文压缩 → LLM 生成/引用`；Agent 在其上增加 `规划 → 工具调用 → 观察 → 反思/循环`。

#### Chunking（分块）与 Metadata

- **描述**：将文档按固定长度、语义段落或层级切为 chunk，并保存标题、来源、时间、权限等元数据。
- **与整篇投喂的区别**：把超长文档转为可索引、可召回的最小知识单元。
- **优点**：提高检索粒度、便于引用和增量更新。
- **缺点/注意点**：chunk 过小丢上下文，过大降低召回精度并浪费窗口；metadata 过滤常比单纯向量检索更关键。

#### Embedding、向量检索与关键词检索（BM25）

- **Embedding 描述**：将 query/chunk 编码为稠密向量，以余弦或内积检索语义相近内容。
- **BM25 描述**：按词频、逆文档频率与长度归一化检索关键词。
- **与彼此的区别**：向量检索擅长语义改写，BM25 擅长精确术语、编号和罕见实体。
- **优点**：混合检索结合两者可提高召回覆盖与鲁棒性。
- **缺点/注意点**：embedding 模型、归一化和索引版本必须一致；向量“相近”不代表内容能支撑答案。

#### ANN 索引：Flat、HNSW 与 IVF

- **Flat 描述**：全量精确搜索；**HNSW**：图结构近邻搜索；**IVF**：先聚类再只搜部分倒排桶。
- **与精确检索的区别**：HNSW/IVF 以少量召回损失换查询速度与内存可控性。
- **优点**：能在大规模语料上满足在线延迟。
- **缺点/注意点**：`efSearch`、`nprobe` 等参数影响 recall—latency；索引更新、过滤和内存成本需纳入运维。

#### Query Rewrite、HyDE 与 Multi-query

- **Query Rewrite 描述**：将用户问题改写为更适合检索的查询；**HyDE**：先生成假设答案再检索；**Multi-query**：生成多个改写并合并召回。
- **与直接检索的区别**：主动弥合用户表达与文档表述的词汇/语义差。
- **优点**：对口语化、复杂或多跳问题常提升召回。
- **缺点/注意点**：改写可能偏离原意，增加模型调用和延迟；应保留原 query 并可观察改写效果。

#### Reranker、Cross-Encoder 与 Context Compression

- **Reranker 描述**：对 query—document 对做更精确相关性打分；Cross-Encoder 让二者共同编码，通常比双塔 embedding 精确。
- **Context Compression 描述**：从候选 chunk 中抽取/压缩与问题相关片段。
- **与第一阶段召回的区别**：召回追求高覆盖，重排/压缩追求高精度和上下文预算控制。
- **优点**：减少无关上下文，提升生成可依据性。
- **缺点/注意点**：Cross-Encoder 较慢；压缩器可能删掉关键限定条件，必须评测最终 answer grounding。

#### RAG、引用与 Grounding

- **描述**：让 LLM 基于检索上下文回答，并输出来源、拒答或不确定性说明。
- **与微调的区别**：RAG 在推理时外挂可更新知识；微调把能力/知识写进权重。
- **优点**：知识更新快、支持私有文档和可追溯引用。
- **缺点/注意点**：检索错、上下文冲突或模型不遵循证据仍会幻觉；“给了引用”不等于引用真正支持结论。

#### Agent：Planner、Tool、Memory、Observation 与 Reflection

- **Planner 描述**：将目标拆成步骤；**Tool**：搜索、数据库、代码、API 等外部能力；**Observation**：记录工具结果；**Memory**：保存跨轮状态；**Reflection**：根据失败/反馈调整策略。
- **与 RAG 的区别**：RAG 多是一次检索—生成；Agent 可循环调用工具并改变后续行动。
- **优点**：可处理多步、动态和可执行任务。
- **缺点/注意点**：状态膨胀、工具失败、提示注入、权限越界和循环失控是核心风险；需设置预算、停止条件与人工确认。
